# Light Tracker server

Приймає запити `GET /api/light/:id` від ESP-пристроїв (кожні 30 с) і пише в Telegram:

- **«Світло з'явилося»**: перший запит після стану «вимкнено»;
- **«Світло вимкнено»**: пристрій пропустив `MISSED_HEARTBEATS` запитів (за замовчуванням 3 × 30 с = 90 с);
- **щоденна статистика** о 23:55 (у неділю ще й тижнева, окремим повідомленням) з таблицею «світло по півгодинах» (добові лічильники скидаються о 00:00; часовий пояс `TZ`, за замовчуванням Europe/Kyiv).

Написано на TypeScript (`src/*.ts`), збирається в `dist/`. Потрібен Node.js 22.9 або новіший; у runtime залежностей немає, `typescript` потрібен лише для збірки.

## Налаштування

1. Створіть бота в [@BotFather](https://t.me/BotFather) і отримайте токен.
2. `cp .env.example .env` і вставте `TELEGRAM_BOT_TOKEN`.
3. `npm ci && npm run build`, потім `npm start` (`npm run dev` збирає й одразу запускає; `npm run typecheck` лише перевіряє типи)
4. Напишіть боту `/start` (в особистих або в групі): він відповість ID чату.
5. Додайте пристрій командою `/add deviceId Дім, вул. Прикладна 1`.
   `id` — те саме, що в кінці URL у скетчі (`/api/light/deviceId`).

### Команди бота

| Команда | Що робить |
|---|---|
| `/start` | ID чату та довідка |
| `/add <id> [назва]` | підписує цей чат на пристрій; якщо пристрою немає — створює. Назва — як цей чат бачитиме пристрій, інші чати її не змінює |
| `/remove <id>` | відписує цей чат від пристрою (сам пристрій лишається) |
| `/list` | пристрої цього чату та їхній стан |

Щоб сторонні не могли додавати пристрої, впишіть свої ID чатів у `BOT_ALLOWED_CHAT_IDS` в `.env`.

### Адмін

У `.env` вкажіть `ADMIN_CHAT_ID` (ID вашого чату з `/start`). Тоді:
- при кожному запуску сервера адмін отримує повідомлення «Сервер перезавантажено»;
- тільки адмін може виконати `/restart`, щоб перезапустити сервер. Інші чати цю команду ігнорують.

- `/unassigned` показує пристрої, що шлють запити, але без жодного чату: нові id, яких немає в `devices.json` (сервер відповідає їм 404, але запам'ятовує до 100 останніх), і пристрої без підписаних чатів. Далі додайте потрібний командою `/add <id> [назва]`. Для інших чатів команда мовчить.

Команда `/restart` завершує процес, а systemd піднімає його знову. Без systemd (наприклад, `npm start` вручну) сервер після `/restart` просто зупиниться.

### devices.json

Команди бота зберігають пристрої в `devices.json`. Кожен пристрій має список чатів, і кожен чат бачить свою назву:

```json
[
  {
    "id": "deviceId",
    "chats": [
      { "chatId": 123456789, "name": "Дім, вул. Прикладна 1" },
      { "chatId": -1001234567890, "name": "Квартира" }
    ]
  }
]
```

Файл можна редагувати й вручну, на ходу: сервер перечитує його за кілька секунд. Якщо прибрати пристрій із файлу, його статистика теж видаляється.

Старий формат (`name` на рівні пристрою і `chatIds`) сервер підхопить сам і перепише файл у новому форматі: назва пристрою стане назвою для кожного чату зі списку.

## Файли

| Файл | Що в ньому |
|---|---|
| `devices.json` | id пристрою і чати з назвою для кожного чату (редагуєте ви або бот) |
| `data/state.json` | статус, час останньої зміни, години, перемикання, добова статистика (пише сервер) |

## Запуск на сервері (Ubuntu)

1. Встановіть Node.js 22.9+ і git, склонуйте репозиторій.
2. Відкрийте TCP-порт 8080 у firewall / Security Group.
3. Встановіть сервіс (за потреби попросить sudo; створить `.env` і `devices.json` з прикладів, якщо їх немає):

```bash
cd <репозиторій>/server
./service.sh install
```

Після цього впишіть токен у `.env`, пристрої в `devices.json` і виконайте `./service.sh restart`.

| Команда | Що робить |
|---|---|
| `./service.sh install` | збирає проєкт, створює systemd-сервіс `light-tracker` і запускає його |
| `./service.sh unit` | лише оновлює unit-файл (запуск `dist/server.js`), без збірки |
| `./service.sh uninstall` | зупиняє й видаляє сервіс (`.env`, `devices.json`, `data/` лишаються) |
| `./service.sh restart` / `status` / `logs` | перезапуск, стан, логи |
| `./update.sh` | скидає локальні зміни, завантажує свіжу версію з git, збирає проєкт (`npm ci && npm run build`) і перезапускає сервіс |

`update.sh` запускайте від власника репозиторію, без sudo. Файли `.env`, `devices.json` і `data/` ігноруються git,
тому оновлення їх не зачіпає.

### Перехід зі старої JavaScript-версії

Старий сервіс запускав `src/server.js`, якого вже немає. Перший раз після оновлення виконайте на сервері вручну:

```bash
cd <репозиторій>/server
git pull
npm ci && npm run build
./service.sh unit      # перепише unit-файл на dist/server.js
./service.sh restart
```

Далі `./update.sh` робить усе сам. Старий `update.sh` на сервері лише завантажить код і перезапустить сервіс, який поки не зможе стартувати. Це нормально, виконайте кроки вище.
